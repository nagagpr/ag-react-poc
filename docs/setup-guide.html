    Deploy on AWS Amplify

    Recommended: connect GitHub (redeploys automatically)

    1. Open the AWS Amplify console and sign in. In the top-right corner, pick a region near your users.
    2. Click Create new app.
    3. Choose GitHub, then Next. A GitHub window asks you to authorize AWS Amplify. Approve it and give it access to the ag-react-poc repository.
    4. Pick repository nagagpr/ag-react-poc and branch main, then click Next.
    5. Build settings: Amplify finds amplify.yml in the repo. It installs Node 22, runs npm ci and npm run build, and publishes the dist folder. Leave the settings as they are and click Next.
    6. Click Save and deploy. Wait until Provision → Build → Deploy are all green, which takes about 2–4 minutes.
    7. Copy the Domain URL, which looks like https://main.d1a2b3c4.amplifyapp.com, and paste it into Your values at the top of this page.
    8. Open the URL in your browser. The grid should load.

    Alternative: upload a zip (no GitHub connection)

    1. Build and zip the site in one command. This creates ag-grid-poc.zip in the project folder.
      powershell
      npm run zip
    2. In Amplify click Create new app → Deploy without Git → Next, enter an app name and a branch name (main), choose Drag and drop, drop the zip, and click Save and deploy.

    Don't zip dist by right-clicking it or with PowerShell's Compress-Archive. Amplify would then show a blank page. Always use npm run zip.

    Create the OutSystems application

    Start on the Service Studio home page that lists your environment's apps (New Application, Install from Forge, and so on). Click Close on any banner.

    1. Click New Application. A dialog titled What are you building? opens.
    2. Pick the application type:
      • Traditional Web (bottom row) matches this POC's plan. Choose it.
      • Reactive Web App (top left) also works if you'd rather try the newer app type. Step 8 has a tab for each.
      • Skip Tablet App, Phone App, External Web Portal and Service.
    3. Click Next. If you're asked to choose a template, pick the default or empty one. Enter the name AGGridPOC and click Create App.
    4. On the application page, click Create Module and keep the suggested name and type. The module editor opens.

    Button names can differ slightly between Service Studio versions. Look for the closest match.

    7

    Add a screen

    1. On the right side of the editor, open the Interface tab. It's one of four tabs: Processes, Interface, Logic, Data.
    2. Expand UI Flows, right-click MainFlow, and choose Add Screen (called Add Web Screen in Traditional Web).
    3. Choose the Empty template, name it AGGridPOC, and click Create Screen.
    4. Right-click the new screen in the tree and choose Mark as Default Screen, so the app opens straight onto it. If that option is greyed out and the screen already has a house icon, it's already the default. Nothing to do.
    5. Select the screen. In the Properties panel (bottom right), under Roles, tick Anonymous so you don't need to log in during the POC. New screens start with only Registered ticked.
    8

    Put the grid on the screen (iframe)

    The widget toolbox is the narrow panel on the left of the editor, with a search box at the top. Choose the tab that matches the app type you picked in step 6.

    Not sure which type you created? Right-click your screen in the Interface tab. If the menu shows Add Client Action or Fetch Data from Other Sources, it's a Reactive Web App. Traditional Web shows Add Preparation and Add Screen Action instead.

    1. Search the toolbox for HTML Element and drag it onto the screen's main content area.
    2. In Properties, set Tag to iframe.
    3. Under Attributes, add each row below. Pick or type the attribute name, then enter the value including the double quotes, because values are OutSystems expressions.
    AttributeValue
    src""
    title"AG Grid POC"
    width"100%"
    height"800"
    style"border:0;display:block;"
    1. Drag an Expression widget onto the screen's main content area.
    2. In Properties, set Escape Content to No. Otherwise the page shows the HTML as text.
    3. Set Value to the text below. It's an OutSystems text, so it's wrapped in double quotes and the HTML inside uses single quotes.
    outsystems expression
    "<iframe src='' title='AG Grid POC' width='100%' height='800' style='border:0;display:block;'></iframe>"

    Optional: make the URL configurable

    1. In the Data tab, right-click Site Properties and choose Add Site Property. Name it AGGridUrl, set Data Type to Text, and set Default Value to: 
      ""
    2. Change the Expression Value to:
      outsystems expression
      "<iframe src='" + Site.AGGridUrl + "' title='AG Grid POC' width='100%' height='800' style='border:0;display:block;'></iframe>"
    3. You can now change the URL in Service Center → Factory → Modules → (your module) → Site Properties without republishing.

    The grid fills whatever height the iframe has. Change 800 to suit your layout.

    10

    Lock down who can embed the grid

    Do this only after step 9 works. That way, if the iframe goes blank, you know this step caused it.

    A. Amplify: only allow your OutSystems site to show the app

    1. In Amplify, open your app, then Hosting → Custom headers → Edit.
    2. Paste the text below and click Save. The address must exactly match your OutSystems page: same https, same host name, no trailing slash.
      yaml
      customHeaders:
  - pattern: '**'
    headers:
      - key: 'Content-Security-Policy'
        value: "frame-ancestors 'self'  http://localhost:5173"
    3. Wait a minute, then reload your OutSystems screen. The grid should still show. Other websites can no longer embed it.

    http://localhost:5173 keeps the local test page from step 3 working. Remove it if you don't need that.

    B. OutSystems: only if Content Security Policy is turned on

    Content Security Policy (CSP) is a setting that controls which sites a page may load. It's usually off in personal environments, and then nothing needs to change. If the OutSystems console shows an error mentioning frame-src or child-src, CSP is on and must allow the Amplify URL:

    1. Open Service Center (/ServiceCenter), or LifeTime if your company uses it.
    2. Go to Administration → Security → Content Security Policy. In LifeTime, look under Environment Security.
    3. Add to Child-src, save, and republish the app. Don't use a * wildcard.
    11

    Optional: load real data from an API (e.g. FastAPI)

    Right now the grid uses built-in sample data. To load data from your own API instead:

    1. The API must return a JSON array with these field names. You can also rename the field entries in src/App.jsx to match your API.
      json
      [{ "orderId": "ORD-1", "orderDate": "2026-05-11", "customer": "Contoso Ltd",
   "country": "India", "product": "Webcam HD", "category": "Electronics",
   "quantity": 3, "unitPrice": 89, "status": "Pending" }]
    2. Allow the grid's addresses in FastAPI (CORS):
      python
      from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173", ""],
    allow_methods=["GET"],
    allow_headers=["*"],
)
    3. For local testing, copy .env.example to .env, set the line below, and restart npm run dev. The footer under the grid shows which data source is in use.
      .env
      VITE_API_URL=http://localhost:8000/orders
    4. For the hosted app, the API must be on a public HTTPS address, because other people's browsers can't reach your PC. In Amplify, go to Hosting → Environment variables, add VITE_API_URL with that HTTPS address, and redeploy.
